# Installed configuration snapshot

This tree tracks the active, versionable installed OpenCode configuration. It is
a source snapshot, not a configuration migration or a guarantee that every
optional runtime integration is available on another machine. The installed
agent models, provider choices and configuration field shapes are preserved.
The source README and evaluation fixtures describe the installed setup and may
contain historical examples; this file records the intentional sync deviations.

## Portability and privacy deviations

- `opencode.json`: `mcp.neurox.command[0]` and
  `mcp.computer-use-linux.command[0]` resolve `neurox` and `computer-use-linux`
  through `PATH`, rather than a particular user's home directory. Installations
  need those existing executables; this sync does not install or start them.
- Credential settings use OpenCode's documented `{env:NAME}` substitution:
  `CONTEXT7_API_KEY`, `FIGMA_API_KEY`, `SLACK_BOT_TOKEN`, and `SLACK_TEAM_ID`.
  Define them in the environment of the OpenCode process. No real credential is
  stored here. The installed `${NAME}` placeholders were not JSON environment
  substitutions; the field shape and provider selection are otherwise unchanged.
- `AGENTS.md`: Nodeterm command examples use `${HOME}/.config/node-terminal`
  instead of a personal absolute home path. Nodeterm is an optional external
  integration; its helper scripts are not bundled or invoked during this sync.
- `plugins/sky-agents/tui.ts` and `plugins/sky-agents-config/index.ts` retain the
  repository's relative wrappers. Their `v2/sky-agents` implementation remains
  repository-owned and unchanged. Installed wrappers referenced absolute paths
  into this same repository, which are not portable.
- `agents/mentor.md`: the private learner profile, preselected personal learning
  goals and assumed background were removed. Generic Spanish mentoring,
  incremental practice, permission boundaries and minimal educational-memory
  instructions remain.
- `README.md`: the Context7 example documents an environment reference instead
  of asking people to paste credentials into configuration.

## Exclusions and preserved repository material

The installed snapshot is intentionally amended by the requested retirement of
agents `linear-orchestrator`, `manager`, and `advisor`, the associated Advisor
plugin/protocol, and all repository custom command definitions. Four obsolete
evaluation fixtures for the removed agent/command flow are also excluded.
These exclusions apply to this source tree and regenerated distribution assets,
not to the globally installed configuration. Remaining skills, MCP integrations,
tools and unrelated plugins are preserved; no replacement aliases are provided.

Do not copy credentials/auth stores, `.env`, service state, installation
manifests, histories, logs, caches, `node_modules`, backups or disabled files.
`service.json` and `.skynex-manifest.json` are installation/runtime state, not
source configuration. Both installed TUI files are retained, including the
`herdr-tui-session.js` reference; no precedence change was attempted.

The installed `bun.lock` declares `@opencode-ai/plugin` version `1.2.27`, while
the installed `package.json` and matching `package-lock.json` declare
`0.0.0-beta-19234`. That stale installed Bun lock is excluded, not regenerated.
The prior repository Bun lock is preserved outside the distributed tree at
`docs/installed-config-archive/bun.lock`. No dependencies were installed.

Repository-only active agents `orchestrator`, `workflow-orchestrator`,
`workflow-reviewer`, `workflow-worker`, and plugin `neurox.ts` are preserved in
`docs/installed-config-archive/` rather than auto-loaded from this tree.
The existing asset generator does not exclude arbitrary archive directories
inside `opencode`, so the archive intentionally lives under `docs`.
Other repository-only documentation, tests, manifests and the Sky Agents
implementation remain. Existing legacy contract tests are not rewritten to
accept the installed prompt policies.

## Runtime limitations and distribution

The diagnostic researcher retains its exact restricted tool declarations:
`diagnostic_read`, `diagnostic_glob`, and `diagnostic_grep`. Their implementation
is a runtime dependency not provided by this snapshot. No generic read tool was
enabled as a fallback. MCP credentials, configured model availability, local
executables, OBS, browser/CDP support, Nodeterm and Herdr are not exercised by
the source synchronization.

Distribution assets are generated by the repository's existing command:

```sh
GOPROXY=off GOTOOLCHAIN=local go run ./cmd/tools/sync-assets/
```

`internal/assets/data/` is generated and Git-ignored except its bootstrap
README. It is not a second independently maintained configuration. The sync
evidence records source, destination, generated and archive hashes; the parent
orchestrator owns review and acceptance.
